# TradeGoPilot

Go-клиент Invest API через gRPC: получение счетов и наблюдатель стакана SBER.

## Запуск

Нужен Go 1.25.3 или новее и токен Invest API выбранного контура.

```sh
cp .env.example .env
# Заполните INVEST_TOKEN в .env локально.
set -a
source .env
set +a
go run ./cmd/tradegopilot
```

Программа читает окружение; файл .env автоматически не загружается.
Если локальный GOROOT указывает на другую версию Go, запускайте
`env -u GOROOT go run ./cmd/tradegopilot` (аналогично для проверок).
Ответ выводится JSON в stdout, tracking-id и ошибки — в stderr.
Пустой список счетов песочницы допустим: программа счета не создаёт.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| INVEST_TOKEN | — | Обязательный токен без префикса Bearer |
| INVEST_ENV | sandbox | sandbox или production |
| INVEST_APP_NAME | roman.TradeGoPilot | Заголовок x-app-name |
| INVEST_TIMEOUT | 10s | Положительный таймаут RPC, включая соединение |

Для реальных счетов задайте INVEST_ENV=production и соответствующий токен.
Для этой команды достаточно доступа только на чтение.
Токен храните в локальном .env, который исключён из Git.

Клиент использует адреса `sandbox-invest-public-api.tbank.ru:443` и
`invest-public-api.tbank.ru:443`. Для проверки TLS к системным корневым
сертификатам добавлен встроенный Russian Trusted Root CA из официального
источника Госуслуг. Устанавливать его в систему не требуется; проверка
сертификата и имени сервера включена. Источник и отпечаток:
[internal/invest/certs/README.md](internal/invest/certs/README.md).

## Структура

- internal/invest — конфигурация и переиспользуемый клиент.
- cmd/tradegopilot — получение счетов; Ctrl+C отменяет запрос.
- cmd/sberwatch — наблюдение за стаканом и сделками SBER/TQBR.
- internal/orderflow — расчёт давления и проверка сигналов через 10/30/60 секунд.

Protobuf-контракты: github.com/tinkoff/invest-api-go-sdk v1.4.6.
SDK архивирован; используется только пакет proto, соединение управляется
напрямую через gRPC. Использованные подписки поддерживаются текущими контрактами;
новые поля API, в том числе выбор источника exchange/dealer, ими не задаются.

## Наблюдатель SBER

Из корня проекта с заполненным `.env`:

```sh
set -a
source .env
set +a
env -u GOROOT go run ./cmd/sberwatch
```

Остановка — Ctrl+C. Для ограниченного запуска добавьте `-duration 2m`.
`-interval 5s` задаёт частоту сигналов (минимум 1s), `-log путь.jsonl` — новый
файл журнала. Существующий файл не перезаписывается. По умолчанию создаётся
`data/sber-<время>.jsonl`; каталог `data/` исключён из Git.
Наблюдатель не выставляет заявки и не требует счёта песочницы.
Он использует `INVEST_ENV` и определяет UID через точный тикер SBER и класс TQBR.

После подтверждения обеих подписок выводит `вверх`, `вниз` или `неопределённо`,
оценку от −100 до +100, середину спреда (mid) и причины. Это эвристическая оценка
давления, **не вероятность и не торговая рекомендация**. Параметры не обучены
и не откалиброваны на истории.

Алгоритм v1:

- Дисбаланс объёмов 10 уровней стакана: вес уровня `1/(номер уровня)`.
- Изменения лучших очередей покупки/продажи с учётом изменения их цены.
- Дисбаланс объёма покупок/продаж в ленте. Объёмы в лотах.
- Итог: `0.45 × стакан + 0.30 × поток заявок + 0.25 × сделки`.
- Окно около 10 секунд, с секундными корзинами для ограничения памяти.
- Для направления нужны модуль оценки ≥0.25, согласие стакана и сделок
  (оба >0.1 для роста или <−0.1 для падения), отсутствие встречного давления
  потока заявок. Также нужны 10 секунд прогрева, ≥3 стакана и ≥3 сделки в окне.
- При спреде >10 базисных пунктов, возрасте стакана >3 секунд, пустом,
  несогласованном или пересечённом стакане направление не выдаётся.
  В неактивные часы нормален ответ `неопределённо`.

JSONL хранит события `session`, `book`, `trade`, `signal`, `evaluation`,
`disconnect`. У каждого сигнала уникальный ID. Направленные сигналы проверяются
по первому свежему стакану с биржевым временем не раньше горизонта 10/30/60 секунд
и не позже него более чем на 3 секунды. Сравнивается mid, а не цена исполнения
сделки; неизменная цена не считается верным направленным прогнозом. Отсутствующие
котировки, разрыв потока и остановка записываются как `unavailable`.
Результаты проверки находятся в журнале в событиях `evaluation`.
Изменение mid не является прибылью: спред, комиссии и исполнение здесь не моделируются.

При разрыве временные ошибки вызывают переподключение с задержкой 1–30 секунд,
история прогрева сбрасывается. Ошибки прав и отклонение подписки завершают процесс.
`INVEST_TIMEOUT` ограничивает поиск инструмента и ожидание подтверждения подписок,
но не длительность наблюдения. При отсутствии любых сообщений 150 секунд поток
перезапускается; ожидание новых данных отображается как `неопределённо`.
